# Planning & Scheduling Roadmaps

**Learn how to turn project scope into a realistic, logical and controllable plan.**

If you want to specialize in **Planning & Scheduling**, this page gives you a practical map of the skills used to develop, maintain, analyze and improve project schedules.

Planning answers:

**What needs to happen?**

Scheduling adds:

**When will it happen, in what sequence, and for how long?**

A simple way to think about the discipline is:

**Scope → WBS → Activities → Logic → Schedule → Baseline → Update → Analyze → Forecast → Recover**

---

## What Does a Planner / Scheduler Do?

A Planner or Scheduler helps the project team understand how work should progress over time.

Typical responsibilities include:

- Understanding project scope
- Developing the WBS
- Defining activities
- Establishing dependencies
- Estimating durations
- Developing schedules
- Setting milestones
- Establishing baselines
- Updating schedules
- Measuring progress
- Analyzing delays
- Forecasting completion
- Supporting recovery planning
- Preparing schedule reports

Scheduling is not simply creating a Gantt chart.

It is understanding the **logic of how work gets done**.

A practical journey looks like:

**Project Fundamentals → Scope → WBS → Activities → Logic → Durations → Calendars → Network → CPM → Float → Baseline → Progress → Updates → Variance → Forecasting → Recovery → Schedule Risk**

## Understand the Project First

Before creating a schedule, understand what the project is trying to deliver.

Learn:

- Objectives
- Scope
- Deliverables
- Requirements
- Milestones
- Constraints
- Assumptions
- Stakeholders

A schedule built without understanding the scope can look detailed while still being fundamentally wrong.

---

## Work Breakdown Structure

The WBS provides the structure for organizing project work.

Understand:

**Project → Deliverables → Work Packages**

Then translate appropriate work packages into activities.

The WBS answers:

**What are we delivering?**

The schedule answers:

**When and in what sequence will we deliver it?**

---

## Activity Definition

Break the planned work into activities that can be:

- Scheduled
- Assigned
- Measured
- Updated
- Controlled

Avoid making activities either:

**Too large → difficult to measure**

or

**Too small → difficult to maintain**

Good activity definition creates a schedule that is detailed enough to control without becoming unnecessarily complicated.

---

## Activity Attributes

Activities may need information such as:

- Activity ID
- Activity name
- WBS code
- Duration
- Calendar
- Resources
- Predecessors
- Successors
- Constraints
- Responsibility
- Progress status

Consistent activity information improves schedule quality.

---

## Dependencies & Logic

Projects contain relationships between activities.

Learn:

- Predecessors
- Successors
- Relationships
- Logical sequencing

Common relationship types include:

**Finish-to-Start**

**Start-to-Start**

**Finish-to-Finish**

**Start-to-Finish**

Understand the logic before worrying about the scheduling software.

---

## Network Diagrams

A network diagram shows how activities connect.

For example:

**A → B → C → D**

This helps you understand:

- Sequence
- Dependencies
- Paths
- Duration
- Critical activities
- Potential delays

The schedule is fundamentally a **network of work**, not merely a collection of bars.

---

## Duration Estimation

Every activity needs a realistic duration.

Learn about:

- Productivity
- Quantities
- Historical data
- Expert judgment
- Resource availability
- Working calendars
- Dependencies
- Uncertainty

Do not simply guess durations.

Ask:

**What assumptions support this duration?**

---

## Calendars

Project schedules operate within working calendars.

Understand:

- Working days
- Non-working days
- Holidays
- Shifts
- Working hours
- Activity calendars
- Resource calendars
- Project calendars

Calendar assumptions can significantly affect completion dates.

---

## Constraints

Constraints limit when or how work can happen.

Examples include:

- Contractual dates
- Access restrictions
- Permits
- Procurement
- Resource availability
- Weather
- Regulatory requirements
- Client milestones

Understand the difference between:

**Logic-driven dates**

and

**Externally imposed dates**

Overusing constraints can hide problems in schedule logic.

---

## Critical Path Method

The **Critical Path Method (CPM)** is a core scheduling concept.

Learn:

- Early Start
- Early Finish
- Late Start
- Late Finish
- Total Float
- Critical Path

The critical path represents the sequence of activities that determines the calculated project completion date under the schedule's assumptions.

---

## Float

Float represents scheduling flexibility.

Learn:

- Total Float
- Free Float
- Float consumption

An activity with available float may be delayed without immediately delaying the overall project completion date, depending on the schedule logic.

Float is not simply "free time."

It is a control signal.

---

## Milestones

Milestones represent important points in a project.

Examples:

- Design complete
- Permit approved
- Procurement complete
- Construction start
- Testing complete
- Handover
- Project completion

Use milestones to communicate major project commitments and events.

---

## Baselines

A baseline represents the approved schedule against which actual performance can be compared.

Learn:

- Baseline dates
- Baseline durations
- Baseline logic
- Baseline milestones
- Baseline management
- Controlled baseline changes

Without a reliable baseline, schedule variance becomes difficult to interpret.

---

## Schedule Updating

A schedule is not finished when it is created.

It must be updated as the project progresses.

Typical update information includes:

- Actual start
- Actual finish
- Remaining duration
- Progress
- Forecast dates
- Logic changes
- Delays
- Constraints

A useful cycle is:

**Status Date → Update → Analyze → Forecast → Report**

---

## Status Date

The status date provides a common point in time for schedule reporting.

It helps distinguish:

**What should have happened by now**

from

**What has actually happened**

Consistent status dates are important for reliable schedule updates and comparisons.

---

## Progress Measurement

Progress must be measured consistently.

Methods may include:

- Milestone completion
- Physical quantities
- Weighted milestones
- Activity completion
- Rules of credit
- Earned progress

Always define what constitutes completion.

Avoid subjective statements such as:

**"The activity is about 70% complete."**

without explaining how the 70% was determined.

---

## Schedule Variance

Compare planned performance with actual performance.

Look for:

- Delayed activities
- Missed milestones
- Critical path movement
- Float consumption
- Out-of-sequence work
- Forecast completion changes

Then ask:

**Why did the variance occur?**

---

## Schedule Analysis

A good scheduler does more than identify late activities.

Analyze:

- Root causes
- Logic changes
- Critical path
- Near-critical paths
- Float trends
- Delays
- Constraints
- Resource issues
- Procurement impacts
- Interface dependencies

The goal is to understand the **cause and consequence** of schedule movement.

---

## Forecasting

A current schedule should provide a view of the expected future.

Forecast:

- Activity completion
- Milestone dates
- Project completion
- Resource needs
- Potential delays

Compare:

**Baseline Finish → Current Forecast Finish**

Then determine:

**What changed?**

**Why?**

**What can still be done?**

---

## Look-Ahead Planning

A detailed schedule can be supported by shorter-term planning.

Common look-ahead horizons include:

- Near-term work
- Upcoming activities
- Constraints
- Required decisions
- Material needs
- Resource needs
- Interfaces

A look-ahead plan helps connect the master schedule with actual field or team execution.

---

## Constraint Management

A planned activity may be delayed because something required for execution is missing.

Track constraints such as:

- Information
- Design
- Approvals
- Materials
- Equipment
- Labor
- Access
- Permits
- Decisions

A useful approach is:

**Identify → Assign Owner → Set Required Date → Remove Constraint → Verify**

---

## Resource Planning

Schedules depend on available resources.

Understand:

- Labor
- Equipment
- Materials
- Capacity
- Availability
- Productivity
- Resource loading

Then explore:

**Resource Leveling**

and

**Resource Smoothing**

The objective is to create a schedule that is achievable—not merely mathematically possible.

---

## Procurement & Schedule

Procurement can strongly influence project schedules.

Understand relationships between:

**Design → Specification → Tender → Award → Manufacturing → Delivery → Installation**

Long-lead items can become critical schedule drivers.

Include important procurement activities and dependencies in the schedule.

---

## Delay Analysis

When a project experiences delay, understand:

- What happened?
- When did it happen?
- Which activities were affected?
- What was the planned sequence?
- What changed?
- Did the critical path change?
- What was the impact on completion?

Delay analysis should be evidence-based.

Avoid assigning blame before understanding the schedule facts.

---

## Recovery Schedules

When a project falls behind, the team may need a recovery strategy.

Possible approaches include:

- Resequencing
- Additional resources
- Extended working hours
- Parallel activities
- Alternative methods
- Procurement acceleration
- Removing constraints

Every recovery action has consequences.

Analyze:

**Time Gain → Cost Impact → Risk → Feasibility**

---

## Schedule Risk

Schedules contain uncertainty.

Explore:

- Schedule risk
- Uncertain durations
- Dependency risk
- Resource risk
- Procurement risk
- External events

Then learn about:

**Schedule Risk Analysis**

The objective is to understand the probability of achieving important dates—not simply produce one deterministic date.

---

## Planning vs Scheduling

These terms are closely related but can be distinguished.

### Planning

Focuses on:

**What needs to be done and how the work will be organized**

### Scheduling

Focuses on:

**When the work will happen and how activities are logically sequenced**

In practice, the two disciplines are tightly connected.

**Forecasting → Recovery → Delay Analysis → Resource Planning → Schedule Risk**
