# Project Controls Roadmaps

**Learn how to measure, analyze, forecast and control project performance.**

If you want to work in **Project Controls**, this page gives you a practical map of the skills used to understand whether a project is progressing according to plan—and what to do when it is not.

Project Controls turns project data into information that supports better decisions.

A simple way to think about it is:

**Plan → Measure → Compare → Forecast → Correct**

---

## What Does Project Controls Do?

Project Controls helps project teams understand project performance.

Typical responsibilities include:

- Developing control structures
- Supporting planning and scheduling
- Tracking progress
- Monitoring cost
- Managing baselines
- Analyzing variances
- Forecasting outcomes
- Supporting change control
- Monitoring risks
- Preparing reports and dashboards
- Maintaining project data quality
- Supporting management decisions

Project Controls is not just reporting.

It connects:

**Scope + Schedule + Cost + Progress + Risk + Change**

---

## Your Project Controls Learning Path

A practical journey looks like:

**Project Fundamentals → WBS → Planning → Scheduling → Cost → Progress → Baselines → Variance Analysis → Forecasting → Risk → Change → Reporting → Performance Management**

Build the fundamentals first.

## Understand the Project First

Before controlling a project, understand what is being delivered.

Learn:

- Project objectives
- Deliverables
- Scope
- Requirements
- Milestones
- Constraints
- Assumptions
- Stakeholders

Then understand how the project is broken into manageable work.

---

## Work Breakdown Structure

The **WBS** provides an important foundation for project controls.

Understand:

**Project → Deliverables → Work Packages**

A good WBS helps connect:

- Scope
- Schedule
- Cost
- Progress
- Responsibility

This creates a common structure for project information.

---

## Control Accounts & Responsibility

Large projects need clear ownership.

Learn how work can be organized around:

- Control accounts
- Work packages
- Responsibility
- Organizational structures
- Cost structures

The objective is to know:

**What work is being controlled?**

**Who is responsible?**

**How will performance be measured?**

---

## Planning & Scheduling

Scheduling is one of the core Project Controls disciplines.

Learn:

- Activities
- Milestones
- Dependencies
- Logic
- Calendars
- Constraints
- Critical path
- Float
- Baselines
- Schedule updates

Then understand:

**Critical Path Method (CPM)**

A schedule is more than a list of dates.

It represents the logical sequence of work.

---

## Schedule Baseline

A baseline represents the approved plan against which actual performance can be compared.

Understand:

- Baseline dates
- Planned activities
- Planned durations
- Planned logic
- Milestones
- Baseline maintenance
- Baseline changes

Without a reliable baseline, meaningful variance analysis becomes difficult.

---

## Progress Measurement

You need a consistent way to determine how much work has actually been completed.

Learn:

- Planned progress
- Actual progress
- Physical progress
- Milestone progress
- Quantity-based progress
- Weighted progress
- Rules of credit

Always ask:

**What does "50% complete" actually mean?**

---

## Schedule Performance

Compare the plan with actual progress.

Look for:

- Early activities
- Late activities
- Slippage
- Critical path movement
- Float consumption
- Missed milestones
- Forecast completion dates

A useful thinking pattern is:

**Baseline → Current Status → Variance → Forecast → Action**

---

## Cost Control

Understand how project costs are planned and monitored.

Learn:

- Cost estimates
- Budgets
- Cost breakdown structures
- Cost baseline
- Actual costs
- Commitments
- Accruals
- Forecasts
- Variances

Cost control is not simply comparing invoices with budgets.

It is understanding:

**What has been spent?**

**What has been committed?**

**What remains?**

**What is the expected final cost?**

---

## Commitments, Actuals & Accruals

Project cost information may exist in different states.

Understand:

### Commitments

Costs that the project is contractually or commercially committed to.

### Actuals

Costs that have been recorded as incurred.

### Accruals

Estimated costs recognized for work or obligations that have occurred but may not yet be recorded as actual costs.

These concepts are important for producing a realistic cost position.

---

## Cost Forecasting

A project team needs to know where the project is heading—not only where it has been.

Learn:

- Estimate to Complete
- Estimate at Completion
- Remaining cost
- Forecast final cost
- Cost variance
- Forecast assumptions

Think:

**Actual + Remaining Forecast = Expected Final Cost**

---

## Earned Value Management

Earned Value Management (EVM) connects scope, schedule and cost performance.

Learn the basic concepts:

- Planned Value (PV)
- Earned Value (EV)
- Actual Cost (AC)

Then understand:

**Schedule Variance**

**Cost Variance**

**Schedule Performance Index**

**Cost Performance Index**

EVM is useful because it connects planned work, completed work and cost information.

---

## Variance Analysis

A variance tells you that actual performance differs from the plan.

But identifying a variance is only the beginning.

Analyze:

1. What changed?
2. Why did it change?
3. What is the impact?
4. Is the variance temporary or continuing?
5. What is the forecast?
6. What action is required?

A good variance analysis explains the **story behind the number**.

---

## Forecasting

Forecasting uses current information to estimate future outcomes.

Forecast:

- Completion dates
- Final costs
- Resource requirements
- Cash requirements
- Potential delays
- Potential overruns

A forecast is not a guarantee.

It is an informed view based on current information and assumptions.

---

## Risk & Opportunity Controls

Project Controls should connect with risk management.

Learn:

- Risk identification
- Probability
- Impact
- Risk exposure
- Mitigation
- Risk owners
- Risk trends
- Opportunities

Then connect risks to:

- Cost
- Schedule
- Scope
- Forecasts

A major risk can become a future cost or schedule variance.

---

## Change Control

Approved changes can alter the project's baseline.

Understand:

- Change requests
- Impact assessment
- Scope impact
- Schedule impact
- Cost impact
- Risk impact
- Approval
- Baseline updates
- Change logs

Never change the baseline simply to make performance appear better.

Baseline changes should be controlled and traceable.

---

## Reporting

Project Controls converts project information into useful reporting.

Typical reports include:

- Progress reports
- Schedule reports
- Cost reports
- Forecast reports
- Risk reports
- Change reports
- Executive summaries
- Performance dashboards

A good report answers:

**Where are we?**

**Where were we supposed to be?**

**Why is there a difference?**

**Where are we heading?**

**What needs to happen next?**

---

## Dashboards

Dashboards should help people understand project performance quickly.

Useful indicators may include:

- Overall status
- Progress
- Schedule variance
- Cost variance
- Forecast
- Critical milestones
- Critical activities
- Major risks
- Major issues
- Change status
- Key actions

Avoid displaying numbers without explaining what they mean.

---

## Data Quality

Project Controls depends on reliable information.

Learn to check:

- Missing data
- Duplicate records
- Incorrect dates
- Inconsistent coding
- Incorrect actuals
- Incorrect progress
- Broken schedule logic
- Unapproved changes
- Stale information

Remember:

**Bad data → Bad analysis → Bad decisions**

## Project Controls vs Project Management

The roles work closely together.

### Project Management

Focuses broadly on:

**Direction → Coordination → Decisions → Delivery**

### Project Controls

Focuses more heavily on:

**Plan → Measure → Analyze → Forecast → Control**

Neither operates effectively in isolation.

---

## Project Controls vs Planning & Scheduling

These disciplines overlap but are not identical.

### Planning & Scheduling

Focuses primarily on:

**How and when the work will happen**

### Project Controls

Has a broader performance focus:

**Scope + Schedule + Cost + Progress + Forecast + Risk + Change**

Scheduling is therefore one important part of Project Controls.
