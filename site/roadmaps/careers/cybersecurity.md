# Cybersecurity Roadmaps

**Protect systems, applications, infrastructure and data.**

If you want to work in **Cybersecurity**, this page helps you understand the skills and concepts used to identify threats, reduce risk and protect technology systems.

You do not need to learn every security tool.

Start with networking, operating systems and software fundamentals, then progress toward identity, application security, cloud security, monitoring, incident response and security engineering.

---

## What Does a Cybersecurity Professional Do?

Cybersecurity professionals help organizations prevent, detect and respond to security problems.

Depending on the role, work may include:

- Protecting applications
- Securing networks
- Managing identities and access
- Finding vulnerabilities
- Monitoring systems
- Investigating security events
- Responding to incidents
- Securing cloud environments
- Protecting data
- Testing security controls
- Designing secure systems
- Improving security processes

A simple way to think about cybersecurity is:

**Understand → Protect → Detect → Respond → Recover → Improve**

---

## Your Cybersecurity Learning Path

A practical journey looks like:

**Foundations → Networking → Linux → Windows → Security Fundamentals → Identity → Encryption → Application Security → Cloud Security → Monitoring → Incident Response → Security Engineering**

You do not need to master every area.

First build a broad foundation, then specialize.

## Recommended Roadmaps

### Start with the Foundations

Security depends on understanding the systems you are protecting.

Start with:

- Networking
- TCP/IP
- DNS
- HTTP/HTTPS
- Linux
- Windows
- Git & GitHub
- Programming fundamentals

If you don't understand how a system works, it is difficult to secure it effectively.

---

## Learn Networking

Networking is one of the most important cybersecurity foundations.

Understand:

- IP addresses
- Subnets
- Ports
- TCP/IP
- DNS
- HTTP
- HTTPS
- Routing
- Firewalls
- Proxies
- Load balancers

Learn how a request travels from one system to another.

Then learn how attackers and defenders can interact with those components.

---

## Learn Operating Systems

Understand how systems work before learning how to secure them.

### Linux

Learn:

- Users
- Groups
- Permissions
- Processes
- Services
- Filesystems
- Logs
- Networking
- Shell commands

### Windows

Learn:

- Users
- Permissions
- Processes
- Services
- Windows security
- Event logs
- Active Directory concepts

You don't need to become an administrator of every operating system.

Understand the security fundamentals first.

## Security Fundamentals

Learn the basic ideas behind cybersecurity.

Understand:

- Assets
- Threats
- Vulnerabilities
- Risks
- Controls
- Attack surfaces
- Security policies
- Security principles

Also understand the three classic security objectives:

**Confidentiality → Integrity → Availability**

---

## Identity & Access Management

Many security problems involve inappropriate access.

Learn:

- Authentication
- Authorization
- Identity
- Roles
- Permissions
- Least privilege
- Multi-factor authentication
- Single sign-on
- IAM

Then explore:

- OAuth 2.0
- OpenID Connect
- JWT
- Identity providers

The key question is:

**Who are you, and what are you allowed to do?**

---

## Cryptography & Encryption

You don't need to become a cryptographer.

Understand the practical concepts:

- Hashing
- Encryption
- Symmetric encryption
- Asymmetric encryption
- Digital signatures
- Certificates
- Keys
- TLS
- PKI

Learn what each mechanism is designed to protect.

---

## Web & Application Security

Modern applications are major security targets.

Learn:

- Input validation
- Authentication
- Authorization
- Session security
- API security
- Secure coding
- Dependency security
- Secrets management

Study common web vulnerabilities through resources such as the **OWASP Top 10**.

The goal is not simply finding vulnerabilities.

It is learning how to prevent them.

---

## API Security

APIs connect applications, services and data.

Learn:

- Authentication
- Authorization
- Access control
- Rate limiting
- Input validation
- API keys
- Tokens
- Secure communication
- API logging

Think about security at every API boundary.

---

## Cloud Security

Cloud environments introduce new security considerations.

Explore:

- Cloud IAM
- Network security
- Storage security
- Encryption
- Secrets
- Logging
- Monitoring
- Secure configuration
- Infrastructure security

Then explore:

- AWS
- Azure
- Google Cloud

Start with one cloud platform.

---

## Container & Kubernetes Security

Modern applications increasingly use containers and orchestration.

Learn:

- Container images
- Image vulnerabilities
- Secrets
- Container permissions
- Network policies
- Kubernetes access control
- Workload security
- Runtime security

Understand container security before moving into advanced Kubernetes security.

---

## Security Monitoring

Prevention is not enough.

Organizations also need to detect suspicious activity.

Learn:

- Logs
- Metrics
- Events
- Alerts
- Security monitoring
- SIEM concepts
- Detection rules
- Threat intelligence

A basic security monitoring flow is:

**Event → Log → Detection → Alert → Investigation**

---

## Incident Response

Security incidents will happen.

Learn how organizations respond.

Understand:

1. Preparation
2. Detection
3. Analysis
4. Containment
5. Eradication
6. Recovery
7. Lessons learned

The goal is not just to stop an incident.

It is also to learn from it and reduce the chance of recurrence.

---

## Threat Modeling

Security should begin before software is deployed.

Learn to identify:

- Assets
- Trust boundaries
- Entry points
- Threats
- Attack paths
- Security controls

A simple approach is:

**What are we protecting? → What can go wrong? → How could it happen? → How do we reduce the risk?**

---

## Zero Trust

Modern security increasingly assumes that trust should not be granted simply because something is inside a network.

Understand principles such as:

- Verify explicitly
- Use least privilege
- Assume breach
- Continuously evaluate access
- Protect resources rather than relying only on network location

Zero Trust is an architectural approach, not simply a product.

## Cybersecurity Specializations

Cybersecurity is a broad field.

Once you understand the fundamentals, you can specialize in areas such as:

### Security Engineering

Build and operate security controls.

### Application Security

Secure software and APIs.

### Cloud Security

Protect cloud infrastructure and workloads.

### SOC / Security Operations

Monitor and respond to security events.

### Penetration Testing

Assess systems by simulating attacks within authorized environments.

### Security Architecture

Design secure systems and technology environments.

### Incident Response

Investigate and respond to security incidents.

You don't need to choose a specialization immediately.

Build the foundation first.

---

## Don't Learn Everything at Once

A common beginner mistake is trying to learn:

**Networking + Linux + penetration testing + cloud + Kubernetes + cryptography + SIEM + everything else**

at the same time.

Don't.

Start with:

**Networking → Linux → Security Fundamentals → Identity → Web Security**

Then move toward:

**Cloud → Monitoring → Incident Response → Security Engineering**

## Cybersecurity vs IT / DevOps

Cybersecurity overlaps with many technology disciplines.

### IT

Often focuses more on:

**Systems → Users → Infrastructure → Support**

### Cloud & DevOps

Often focuses more on:

**Infrastructure → Automation → Delivery → Operations**

### Cybersecurity

Often focuses more on:

**Risk → Protection → Detection → Response**

Strong security professionals understand the systems they are protecting.

---

## Build Projects Safely

Security should be practiced only in systems you own or are explicitly authorized to test.

Build safe projects such as:

- Secure web application
- Authentication system
- Security monitoring dashboard
- Log analysis pipeline
- Threat-modeling exercise
- Secure API
- Cloud security lab
- Container security lab
- Incident-response simulation

Focus on understanding **why** a control works, not just running a security tool.

---

## Your Goal Is Not to Learn Every Security Tool

Security tools change constantly.

Your durable skills are:

**Understand → Assess → Protect → Detect → Respond → Improve**

Learn the underlying principles.

Then you can adapt to new tools and threats.
